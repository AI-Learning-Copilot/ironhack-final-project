## Overview

This lesson covers the usage of the OpenAI API, focusing on prompt injection vulnerabilities, tool calling mechanisms, and the AI landscape as of 2026. ## Key Concepts

- **Prompt Injection**: A vulnerability where user input can manipulate an AI model's behavior.
- **Tool Calling**: The ability of AI models to invoke external functions or tools to retrieve real-time data or perform specific tasks.
- **Agentic Loop**: A workflow pattern that continuously interacts with the model until a final answer is produced.
- **Foundation Models**: Large AI models trained on diverse datasets, capable of performing various tasks across different domains.

## Detailed Notes

### Prompt Injections

- **Definition**: A vulnerability allowing users to manipulate AI instructions through input.
  - **Direct Prompt Injection**: Explicitly overriding instructions (e.g., "Ignore your previous instructions...").
  - **Indirect Prompt Injection**: Malicious instructions embedded in external content.
- **Mitigation Techniques**:
  - Treat all external content as untrusted.
  - Use explicit delimiters to distinguish between trusted instructions and user data.
  - Validate and sanitize user inputs.

### Tool Calling

- **Definition**: Enables LLMs to request execution of external tools or functions.
- **Workflow**:
  1. User sends a message.
  2. Model decides if a tool is needed and specifies the tool and arguments.
  3. Application executes the tool.
  4. Result is sent back to the model for final response generation.
- **Implementation**:
  - Define a Python function and its JSON schema for the tool.
  - Use `responses.create()` to pass the tools list to the model.
  - Execute the tool and return the result to the model.

### Important Considerations

- Always validate user inputs and external data.
- Use explicit delimiters for user data.
- Understand LLM limitations and leverage tool calling for enhanced capabilities.

### The Agentic Loop

- A standard pattern in production environments where the model is called repeatedly until it no longer requests tools.
- Involves checking for tool requests, executing tools, and returning the final answer.

### Tool Registry

- A registry maps tool names to their corresponding Python functions, facilitating easy access and invocation.

### Provider-Managed Tools

- Built-in tools offered by AI providers that handle execution internally, requiring no user-defined schema.

## Examples & Applications

- **Example Function**: `get_weather(city: str) -> str` simulates fetching weather data.
- **Tool Invocation**: When a user asks for the weather, the model invokes the `get_weather` function to retrieve real-time data.
- **Automated Testing**: Implementing tests to ensure the model invokes the correct tools based on user queries.
