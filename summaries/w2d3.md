## Overview

This lesson covers the end-to-end workflow of a supervised learning project, specifically focusing on predicting customer churn using the Telco Customer Churn dataset. It includes problem definition, data loading, exploratory data analysis (EDA), data splitting, data cleaning, baseline modeling, feature engineering, handling class imbalance, model training, and evaluation.

## Key Concepts

- **Supervised Learning**: A type of machine learning where the model is trained on labeled data.
- **Binary Classification**: Predicting one of two outcomes (e.g., churn or no churn).
- **F1-score**: A metric that balances precision and recall, particularly useful in imbalanced datasets.
- **Exploratory Data Analysis (EDA)**: Understanding the dataset and identifying potential issues before modeling.
- **Class Imbalance**: A situation where one class is significantly more frequent than another, affecting model performance.
- **Data Leakage**: Occurs when information not available at prediction time is used during training.
- **Feature Engineering**: The process of creating new features or modifying existing ones to improve model performance.

## Detailed Notes

### 1. Dataset Overview

- **Dataset**: Telco Customer Churn dataset with customer demographics, services used, and account information.
- **Target Variable**: "Churn" (binary classification: "Yes" for churned, "No" for stayed).

### 2. Evaluation Metric

- **F1-score**: Chosen due to its effectiveness in scenarios with class imbalance. It combines precision and recall.

### 3. Data Loading and Exploration

- **Loading Data**: Use pandas to load the dataset from a CSV file.
- **Exploratory Data Analysis (EDA)**:
  - Identify missing values and data quality issues.
  - Check the distribution of the target variable, noting a mild class imbalance (73.5% did not churn, 26.5% churned).
  
### 4. Data Types and Structure

- **Data Type Inspection**: Check how pandas interpreted each column to identify incorrect data types.
- **Suspicious Columns**: For example, "TotalCharges" is numeric but stored as an object.

### 5. Data Splitting

- **Importance**: Prevents data leakage by ensuring transformations are fitted only on the training set.
- **Common Splitting Methods**:
  - **Train/Test Split**: 80% training, 20% testing.
  - **Train/Validation/Test Split**: 70% training, 15% validation, 15% testing.
  - **Cross-Validation**: Provides robust performance estimates.
- **Stratification**: Maintains the proportion of churned vs. non-churned customers across splits.

### 6. Data Cleaning

- **Actions**:
  - Remove the `customerID` column.
  - Fix the `TotalCharges` column by converting it to numeric and addressing missing values.

### 7. Establish a Baseline Model

- **Baseline Model**: A `DummyClassifier` predicting the majority class to serve as a reference point.
- **Evaluation**: High accuracy can be misleading in imbalanced datasets.

### 8. Feature Engineering

- **Importance**: Prepares the dataset for modeling by creating and modifying features.
- **Encoding Categorical Variables**: Use one-hot encoding with `drop='first'` to avoid multicollinearity.
- **Signal Amplification**: Create new features to enhance model learning.

### 9. Handle Class Imbalance

- **Current Dataset Analysis**: Mild imbalance noted; class weights can be used to adjust the loss contribution during training.
- **Methods**:
  - **Data-Level**: Undersampling, oversampling, SMOTE.
  - **Algorithm-Level**: Class weights, threshold tuning.

### 10. Train and Compare Different Models

- **Model Types**: Logistic Regression, Decision Trees, Random Forests, XGBoost.
- **Evaluation Metrics**: F1-score, accuracy, precision, recall.

## Examples & Applications

- **Baseline Model Evaluation**: The baseline model's performance metrics (accuracy, precision, recall, F1-score) highlight the importance of focusing on the minority class.
- **Feature Engineering Example**: Creating features like `is_new_customer` and `num_services` to capture customer behavior.

## Key Takeaways

- Understand the importance of EDA and data cleaning in the modeling process.
- Use F1-score as a primary metric for evaluating model performance in imbalanced datasets.
- Implement feature engineering and selection to improve model accuracy and interpretability.
- Be cautious of data leakage and ensure proper data splitting techniques are applied.
- Regularly evaluate models using validation sets to avoid overfitting and ensure generalization.
