## Overview

This lesson focuses on evaluating the performance of language models (LLMs) and the importance of gathering relevant information before querying the LLM. It covers various evaluation metrics, particularly BLEU and ROUGE, and introduces practical applications through labs.

## Key Concepts

- **Generative Models**: Models that generate new content based on learned patterns from training data.
- **Evaluation Metrics**: Tools used to quantify the performance of models, particularly in tasks like translation and summarization.
- **BLEU**: A metric for evaluating translation quality by comparing generated translations to reference translations.
- **ROUGE**: A set of metrics for evaluating the quality of summaries produced by models.
- **Retrieval-Augmented Generation (RAG)**: A system that combines retrieval of relevant documents with generation of responses.

## Detailed Notes

### Evaluation Metrics for Generative Models

1. **Introduction to Evaluation Metrics**:
   - Traditional metrics like Accuracy, F1 Score, and Recall are unsuitable for generative models.
   - New metrics such as **BLEU**, **ROUGE**, and **METEOR** are introduced.

2. **BLEU Metric**:
   - Evaluates translation quality by comparing generated translations to reference translations.
   - Scores range from 0 to 1, with higher scores indicating better quality.
   - Important to note that BLEU does not equate to correctness; human judgment is essential.

3. **Implementation Steps for BLEU Evaluation**:
   - Install dependencies (e.g., `transformers`, `deep-translator`, `evaluate`).
   - Load the NLLB model and tokenizer from Hugging Face.
   - Create a translation pipeline and store translations for evaluation.

4. **ROUGE Metrics**:
   - Measures the quality of summaries by evaluating n-gram overlap with reference summaries.
   - Key variants include ROUGE-1, ROUGE-2, ROUGE-L, and ROUGE-Lsum.

5. **Implementation Steps for ROUGE Evaluation**:
   - Install required libraries (e.g., `rouge_score`, `evaluate`, `datasets`).
   - Load a dataset (e.g., from Kaggle) and extract relevant text for evaluation.

### Model Comparison for Summarization

1. **Models Used**:
   - **`t5-base`**: Original T5 model, not fine-tuned.
   - **`flax-community/t5-base-cnn-dm`**: Fine-tuned version for summarization.

2. **Summarization Function**:
   - The `create_summaries` function generates summaries using the model's `generate` method.

3. **Evaluation Metrics**:
   - ROUGE scores are computed to compare generated summaries against reference summaries.

### Evaluation of System Performance

1. **Information Gathering**:
   - Essential to gather relevant information before querying the LLM.

2. **Groundness**:
   - Checks if LLM responses are based on provided documents.

3. **End-to-End Evaluation**:
   - Comparing LLM outputs against reference answers for comprehensive evaluation.

4. **Using LLM as a Judge**:
   - LLMs can evaluate the quality of responses based on defined metrics.

5. **Implementation Steps**:
   - Load models and prepare evaluation metrics using OOP principles.

## Examples & Applications

- **BLEU Evaluation for Translations**: Students perform translations using the NLLB-200-distilled-600M model and evaluate using BLEU scores.
- **ROUGE Evaluation for Summarization**: Students generate summaries using different models and compare their performance using ROUGE metrics.

## Key Takeaways

- BLEU and ROUGE are essential metrics for evaluating translations and summaries, respectively.
- Human judgment is crucial in assessing the quality of translations and summaries.
- Understanding the strengths and limitations of evaluation metrics is vital for effective model assessment.
